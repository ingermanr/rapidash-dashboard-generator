# Professional hardening — Rapidash Dashboard Generator

Objective: make the project professional in phases (baseline+CI → domain → UI → product). Branch: `chore/professional-baseline`.
Delivery: ask-on-risk, work-unit commits. Test runner: `npx jest`; checks: `npx tsc --noEmit`, `npm run lint`, `npm run build`.

## Specs

- S1 Phase 1 "Base": normalize EOL, fix type errors, single lockfile, clean dependencies and `console`, migrate ESLint to flat config, add CI (types + lint + tests + build).
- S2 Phase 2 "Dominio": extract combination generation, layout selection and mock data to `lib/domain/` with a seeded RNG and unit tests.
- S3 Phase 3 "UI": split the two giant components (layouts, charts, cards) and add behavior tests.
- S4 Phase 4 "Producto": PDF, accessibility, persistence (to be defined with the user).
- S5 Accessibility (user: "vamos con cualquiera de los dos" — accessibility chosen over persistence): zero axe violations on landing, builder (empty and with a variant) and detail in light and dark; WCAG AA text contrast (4.5, 3 for large text) including text over gradients; icon-only buttons named and visible on keyboard focus; charts with a text alternative; `prefers-reduced-motion` respected; landing copy matches the product.

- S6 Persistence (user picked "Varios dashboards guardados (Recomendado)": "Lista local de dashboards: guardar, abrir, renombrar y borrar. Empezar uno nuevo ya no pierde el anterior. Sigue todo en el navegador, sin backend."). Plus hygiene found while exploring: versioned persisted schema with a migration (existing single-dashboard data becomes the first saved dashboard, nothing lost); remove the unused `ui-store`.
- S7 Storage failures (user: "vamos con la más importante de las 4" → quota chosen as the only silent data-loss risk): a failed write (full or blocked localStorage) never throws from a user action, the user sees what happened and what to do, and the warning clears once a write succeeds.
- S8 Corrupted storage (user: "vamos con datos corruptos"): whatever is in `dashboard-storage` (other tabs, older versions, manual edits) must not crash the app; unusable items are dropped, the rest is repaired; valid data must pass through unchanged.
- S9 Export / import JSON (user: "vamos con la 1" → "Exportar / importar JSON": "Descargar un dashboard como archivo .json y volver a cargarlo, sirve como respaldo o para pasarlo a otra máquina. Con validación del archivo."). Defaults chosen (no product decision open): export per dashboard and "Exportar todos"; "Importar dashboards" always visible on the landing; file `{ format: "dashboard-generator", version: 1, exportedAt, dashboards }`; import sanitizes, never overwrites (clashing ids get a new id), imported dashboards go first, a toast reports imported and discarded counts and explains invalid files.
- S10 Share link (user: "dale, lo hacemos" → chose "Definición + layout actual (Recomendado)": "Título, descripción, variables, exclusiones y el layout que estás viendo. Link corto (~2-4 KB) que funciona en chats y correos. Quien lo abre ve exactamente ese layout y puede guardarlo o generar más."). Payload in the URL fragment (`#share=`, never sent to the server), deflate-raw + base64url with an uncompressed fallback; "Compartir" in the detail view copies the link (manual copy field when the clipboard is unavailable); opening a link creates a new dashboard with that layout (never overwrites), clears the fragment, sanitizes everything, and a broken link shows a message. After S10 the user wants another sweep of the app and to discuss proposals for the future.
