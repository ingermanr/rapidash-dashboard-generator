# Professional hardening — Rapidash Dashboard Generator

Objective: make the project professional in phases (baseline+CI → domain → UI → product). Branch: `chore/professional-baseline`.
Delivery: ask-on-risk, work-unit commits. Test runner: `npx jest`; checks: `npx tsc --noEmit`, `npm run lint`, `npm run build`.

## Specs

- S1 Phase 1 "Base": normalize EOL, fix type errors, single lockfile, clean dependencies and `console`, migrate ESLint to flat config, add CI (types + lint + tests + build).
- S2 Phase 2 "Dominio": extract combination generation, layout selection and mock data to `lib/domain/` with a seeded RNG and unit tests.
- S3 Phase 3 "UI": split the two giant components (layouts, charts, cards) and add behavior tests.
- S4 Phase 4 "Producto": PDF, accessibility, persistence (to be defined with the user).
- S5 Accessibility (user: "vamos con cualquiera de los dos" — accessibility chosen over persistence): zero axe violations on landing, builder (empty and with a variant) and detail in light and dark; WCAG AA text contrast (4.5, 3 for large text) including text over gradients; icon-only buttons named and visible on keyboard focus; charts with a text alternative; `prefers-reduced-motion` respected; landing copy matches the product.

- S6 Persistence (user picked "Varios dashboards guardados (Recomendado)": "Lista local de dashboards: guardar, abrir, renombrar y borrar. Empezar uno nuevo ya no pierde el anterior. Sigue todo en el navegador, sin backend."). Plus hygiene found while exploring: versioned persisted schema with a migration (existing single-dashboard data becomes the first saved dashboard, nothing lost); remove the unused `ui-store`.
